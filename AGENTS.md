# AGENTS.md — working rules for Nigeria State Monitor

This file is the contract for any future human or AI coding session. Read it before changing code.

## 1. Product invariants (non-negotiable)

1. **Never approximate Nigeria's map.** Boundaries come from the checked-in GRID3/geoBoundaries GeoJSON, generated by `scripts/build-geo.mjs`. Do not hand-draw, redraw, nudge or "fix" geometry.
2. **Never fabricate production data.** No invented events, sources, URLs, economic values, coordinates or sync timestamps. Demo content lives only in `src/lib/demo/` and must have `isDemo: true`; it must never enter a production data path.
3. **One event ≠ one article.** Article-level records and event-level intelligence are separate. Do not present article counts as unique incidents.
4. **Volume is not risk.** Reported-event volume must always be labelled as such. Never derive a "danger score" or state safety ranking from news counts.
5. **Coordinates need evidence.** Each event has `geoPrecision: "exact" | "lga" | "state"`. LGA/state markers are centroids, not incident locations, and the UI must say so. Never invent coordinates.
6. **Facts, analysis and uncertainty are separate.** AI/automated text is visually labelled. Verification status, source independence and confidence are visible. Allegations are not facts.
7. **No fake live behaviour.** If ingestion is not connected, say so. Do not simulate production updates. Demo updates are allowed only when clearly labelled `DEMO DATA — NOT A REAL INCIDENT`.
8. **Every visible control must work.** Disable or omit features that are not implemented. Do not ship decorative buttons.
9. **Low-bandwidth is a product requirement, not a later optimisation.** Keep the SVG map path dependency-free and MapLibre lazily loaded.
10. **No credentials in the client.** Server-only env vars must never be prefixed `NEXT_PUBLIC_`.

## 2. Architecture

```
src/app/            Next.js App Router routes, API handlers
src/components/     UI + dashboard components; ui/ for shadcn-style primitives
src/lib/geo/        state registry, projection, map helpers
src/lib/data/       repository interface, in-memory demo repository, Postgres/PostGIS repository
src/lib/demo/       fictional dataset only
src/lib/ingestion/  RSS fetch, parse, validation, deterministic priors and review proposals
src/lib/review/     reviewer decision rules, queue and audit contracts
src/lib/ai/         enrichment provider boundary, prompts, schema validation and runner
src/lib/clustering/ category + geography + time gates and deterministic similarity scoring
src/lib/verification/ evidence-gated verification state machine and transition rules
src/lib/intelligence/  filtering, aggregation, assessments
src/lib/validation/ Zod schemas shared by APIs and UI
src/data/           generated geography + registry (do not hand-edit generated files)
scripts/            reproducible data generation, ingestion and maintenance
docs/               architecture and operational documentation
supabase/migrations Production Postgres/PostGIS migrations (+ supabase/rollbacks)
```

- **Server components** render the shell and initial snapshot.
- **Client components** own interactive filtering. Zustand is the single source of filter truth.
- **TanStack Query** handles health/sync and search requests; do not duplicate server state in Zustand.
- **Repository boundary.** Components must not import demo data or database drivers directly. They receive typed data through the repository/API layer. `NSM_REPOSITORY=memory|postgres` selects the backend; production mode requires Postgres.
- **Bulk data access.** Server components and API routes use the repository. No direct SQL outside `src/lib/data/postgres` or database scripts, and no per-event N+1 queries. Background jobs perform writes.
- **Ingestion boundary.** `src/lib/ingestion/` captures publisher evidence; `src/lib/data/postgres/ingestion.ts` persists it. Capture writes `raw_items`, `articles`, `ingestion_candidates`, `ingestion_logs` and `source_health` only. It must never create or update an event. A candidate is `pending`, `needs_review` or `rejected` from capture; `accepted` is reachable only through `src/lib/review/` + `src/lib/data/postgres/review.ts` (CLI-only).
- **Reviewer boundary.** `scripts/review/run.ts` may accept or reject a candidate with a stable operator ID. Acceptance requires a category and state, writes an append-only `candidate_reviews` row in the same transaction, and never creates, verifies or publishes an event. Rejection requires a rationale. Every review endpoint and UI must stay behind reviewer authentication (`src/lib/auth/`).
- **AI enrichment boundary.** `src/lib/ai/` may call a provider and store a validated proposal; it must never update a candidate or create, verify or publish an event. `AI_PROVIDER` defaults to `disabled`; `openai` and `openai-compatible` are implemented, and any other value must raise `AiConfigurationError` rather than fall back. Geography must match the authoritative registry/LGA gazetteer, and location evidence must be an exact title/excerpt phrase. Raw response text is never stored, only its SHA-256 hash. `ai_enrichments` is append-only and server-only. Do not claim a model is active without a real provider and hosted/real-call evidence.
- **Clustering boundary.** `src/lib/clustering/` is a pure assessment. Distinct records, a resolved equal category, a resolved equal state and report times within 72 hours are hard gates before similarity. A high score never overrides an LGA conflict, contradictory headline numbers, same-publisher evidence or a shared independence group. 0.86 may auto-attach only with independent evidence and no conflict; 0.70–0.86 goes to review; below 0.70 stays separate. Never merge events from similarity alone. Cluster persistence and review exist (`scripts/cluster/run.ts`, `/review`); never merge or attach from similarity alone.
- **Verification boundary.** `src/lib/verification/` is a pure state machine; `src/lib/data/postgres/verification.ts` applies an approved transition to an existing event only. Independent groups, not article counts, drive `single_source`/`multiple_sources`/`corroborated`. A shared publisher or `independence_group` is one group. `corroborated` requires explicit reviewer approval and no conflict; `retracted` requires retraction evidence and is terminal. The store updates `events`, appends `event_updates` and writes `audit_logs` in one transaction. It must never create an event, change `published`, alter confidence or write a public view. Verification is exposed through `scripts/verification/run.ts` and the authenticated `/review` console.
- **Feed fetching.** One feed retrieval per run (at most three revalidated redirect hops). HTTPS only, exact host allow-list revalidated on redirects, no article-page fetch, no arbitrary link following, truthful User-Agent, timeout, byte ceiling and strict RSS content type. Reject DTD/ENTITY declarations. Never store the raw feed body, full article text, images or author PII.
- **Source admission.** Do not add a source until its feed, robots.txt and terms are verified and recorded in `docs/DATA_SOURCES.md`. Mark it `approved`, `restricted` or `unreviewed`; never claim `approved` without evidence. One source must stay green end-to-end before adding another.
- **Deterministic priors first.** Category and state/LGA priors run before any AI proposal. Ambiguous geography, unresolved category/state, low confidence or a missing publication date becomes `needs_review`, never a guess. "Niger" alone is not Niger State and "Niger Delta" is not Delta State.
- **Hosted Postgres rules.** Runtime reads `DATABASE_URL`; admin scripts prefer `MIGRATION_DATABASE_URL`. Both are server-only. PostGIS lives in the `extensions` schema, and runtime SQL schema-qualifies PostGIS (`extensions.ST_*`, `extensions.geometry`, `extensions.geography`). Do not reintroduce unqualified PostGIS calls in runtime paths: the Supabase transaction pooler may ignore startup `search_path` options. Migrations must set `search_path = public, extensions` themselves. Any future migration that creates a table in `public` must enable RLS and revoke default `anon`/`authenticated` grants; Supabase can grant new public tables automatically.

## 3. Geographic rules

- The canonical registry is `src/data/state-registry.json`. All 37 entries, unique IDs, ISO-shaped internal codes, six zones.
- Generated metadata: `src/data/states.generated.json` and `src/data/nigeria-svg-map.json`; generated public geometry: `public/data/nigeria-states.geojson`. Regenerate with `npm run geo:build`; never hand-edit.
- IDs follow `NG-XX` as defined by the product spec. They are internal identifiers, not official ISO codes.
- Zone membership is fixed in `src/lib/geo/zones.ts`. FCT belongs to North Central.
- Labels use representative interior points (polylabel), not bounding-box centres.
- Map hover/click must be available through a keyboard-accessible state picker as well. SVG and MapLibre must expose the same selection semantics.

## 4. Data and API rules

- All API input is parsed with Zod. Invalid input returns `400` with a stable error envelope.
- All API output is typed and cached appropriately. Never leak stack traces or raw upstream content.
- Filters: `state`, `zone`, `category`, `severity`, `window`, `q`, `limit`, `offset`.
- `limit` is capped (default 25, max 100). Time windows are `24h | 7d | 30d | 90d | 365d | all`.
- Error envelope: `{ error: { code, message, details? }, requestId }`.
- No N+1 queries. Aggregate in SQL or in a single repository method.
- Demo datasets must be marked at response level with `meta.mode: "demo"` and row level with `isDemo`.

## 5. AI rules (Phase 5+)

- The LLM never writes directly to an event record. Enrichment is a proposal; deterministic validation and (where needed) human review accept it.
- `AI_PROVIDER` defaults to `disabled`. Only `disabled`, `openai` and `openai-compatible` are implemented; any other value must fail loudly and make no call.
- Store `provider`, `model`, `prompt_version`, `schema_version`, `processed_at`, confidence and raw response hash for every enrichment. Store the validated proposal only; never raw response text.
- The proposal must not contain severity, coordinates, verification status, event identity or URLs. Unknowns must be `null`, not guesses.
- Geography must match the authoritative state registry and LGA gazetteer, and each location-evidence phrase must appear verbatim in the supplied title or excerpt.
- `ai_enrichments` is append-only and server-only. AI output must never update a candidate, create an event, set verification status or publish.
- Preserve the original headline, URL, excerpt, published time and retrieved time unchanged.
- Never merge events from similarity alone. Require category + geography + time-window gates, then similarity; uncertain pairs go to review.
- Multiple articles from one publisher or syndicated copies are not independent corroboration.
- AI analysis is always separated from reported facts and labelled as analysis.

## 6. Frontend conventions

- TypeScript strict; no `any` without a written justification.
- Tailwind v4 tokens in `src/app/globals.css`. Use the defined palette; no random hex values in components.
- shadcn-style primitives live in `src/components/ui/`. Radix is the behaviour layer.
- Numeric/timestamp values use `font-mono` (JetBrains Mono). Body uses Inter.
- All interactive components need focus-visible styling and accessible names. Test keyboard paths.
- Motion: use Framer Motion only for meaningful state transitions; respect `prefers-reduced-motion` and lite mode.
- Empty, loading, error and offline states are required for every data surface.
- No images or external fonts/tiles in Phase 2. The app must render without third-party network access.

## 7. Testing requirements

- Any change to the registry, geo pipeline, filters, aggregation or demo data: update/extend Vitest tests.
- Any change to interactive UI: add RTL coverage for state changes and accessible names.
- Any change to the database schema, repository SQL or connection settings: update the PGlite/PostGIS suite and/or `src/lib/data/postgres/client.test.ts`, then run `npm run db:verify:local`.
- Any change to ingestion fetch, parsing, URL guards, classification or persistence: add tests for the failure path as well as the happy path, then run `npm run ingest:dry-run` and `npm run ingest:local` before claiming the source works.
- Any change to reviewer decisions, queue SQL or audit behaviour: update the pure decision tests and the PGlite/PostGIS review suite, then run `npm run db:verify:local`. Never claim publication, verification or reviewer authentication from this path.
- Any change to AI prompts, schema validation, provider configuration or enrichment storage: update the AI unit tests and the PGlite/PostGIS AI store suite, then run `npm run db:verify:local`. Never claim a live model call without a real provider and recorded output.
- Any change to clustering gates, similarity scoring or conflict handling: update the pure clustering tests. Never describe a score as a merge unless the category, geography and time gates passed and evidence is independent.
- Any change to verification rules or the verification store: update the pure transition tests and the PGlite/PostGIS verification suite, then run `npm run db:verify:local`. Never claim publication, a verification CLI/UI or reviewer authentication from this path.
- Hosted Supabase changes must keep `npm run db:doctor` and `npm run db:verify` credible. Do not claim a hosted run without connection strings and output.
- Before claiming a phase complete: `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`.
- Browser verification is mandatory for map/selection changes: desktop + 390px viewport, console clean, real interaction (not just screenshot).
- Playwright suite is the acceptance gate from Phase 9. Keep `data-testid` stable (`state-path-NG-IM`, `event-card-<id>`, etc.).

## 8. Phase discipline

Follow `docs/ARCHITECTURE.md` phase order. Do not add later-phase UI that pretends to work. When a phase ends, update `README.md` status and report: implemented, files, tests, results, limitations, configuration, next phase.

## 10. Data-source etiquette

- Respect robots.txt, feed terms and rate limits.
- Prefer official APIs and RSS over scraping.
- Identify NSM with a truthful User-Agent and contact in production.
- Do not republish full article text. Store only what is needed for evidence and link to the publisher.
- Premium Times is `restricted`: headline, ≤320-character excerpt, timestamps, feed categories, attribution and outbound link only. No full text, images, author PII or raw feed payload.
- Before adding a source, record verification evidence and licence/terms status in `docs/DATA_SOURCES.md`.


## Economy, history and offline rules (added with Phases 6–8)

- **Economic figures are never written into the repository or invented.** `src/lib/economy` only reads World Bank series for Nigeria from `api.worldbank.org` (the host is allow-listed), validates every response with Zod, omits years without a value and never interpolates. Each indicator keeps its own reference year; never compare or combine different periods. Test fixtures must use obviously synthetic numbers.
- **History must say what is not held.** `buildHistory` marks buckets outside the held records as `observed: false` and the coverage note must stay visible in the UI. Never imply that an empty bucket outside coverage was quiet. Counts are reported volume, not incidence or risk.
- **`/api/events` must keep rejecting `from`/`to`**; custom ranges belong to `/api/intelligence/history`. Never silently ignore a filter the caller believes was applied.
- **Rate limiting is asynchronous.** Always `await enforceRateLimit(...)` (and `guardReviewRoute`). Upstash failures fall back to the in-memory limiter, never to "allow everything".
- **Service worker (`public/sw.js`):** never cache `/api/review`, `/api/cron`, `/api/system/health` or `/review`; never cache non-200 responses; saved responses must be labelled (`X-NSM-Served-From`) and announced to the page. Caches are named after the build id (`/sw.js?v=<id>`), so every deployment starts clean. A slow network shows the saved copy but must let the real request finish and refresh the cache. Do not make the page re-send its assets to the worker on every load (only on `controllerchange`).
- Heavy chart dialogs (Economy, History) are loaded with `next/dynamic` on first open to protect first-load size (currently about 209 kB). Check `npm run build` output before adding imports to the main bundle.

## News sources and wording rules (added 9 November 2026)

- **Never add a source without evidence, and label it honestly.** Every entry in `INGESTION_SOURCES` needs an entry in `SOURCE_EVIDENCE` stating its level: `verified` (observed returning RSS first-hand, with a date), `third_party` (a reader or relay shows recent posts) or `directory` (listed in a feed directory). Never present a `directory` source as verified. Guessed URLs belong only in `UNVERIFIED_FEED_CANDIDATES`. Run `npm run sources:check` before promoting a candidate. Every source is `restricted` unless its licence was reviewed. The default is `INGESTION_SOURCE=all`; runtime isolation, not optimism, is what makes that safe.
- **robots.txt is enforced in `runIngestion`** (`enforceRobots` defaults to true; only tests turn it off). An unreadable or disallowing robots.txt means no feed request. Do not add a path that fetches a feed without it. Keep one `independenceGroup` per publisher.
- **Interface wording follows the dataset mode.** Never hardcode "demo" or "fictional" in a component; use `useDatasetLabels()` (`src/lib/dataset-labels.tsx`) or an `isDemo` condition. Real published records must never be described as demo, fictional or "not a real incident".

## Automatic publishing rules (added 12 November 2026)

- Publishing is automatic by the owner's decision. Keep every automatic decision attributable to the actor `system.autopublish` (`AUTOPILOT_ACTOR`) and never to a person, and keep the on-screen wording that says records are published automatically and not reviewed by a person.
- Software-assigned severity must stay capped at 3. Do not let any automatic path assign 4 or 5, mark an event corroborated or official, or write an AI analysis as fact.
- Publish one article at a time and run the duplicate check before each publish (`runAutopilot`). Do not bulk-publish accepted candidates: that creates duplicate events.
- An AI proposal is used only when it passed validation (verbatim location evidence) and meets `AUTOPUBLISH_MIN_AI_CONFIDENCE`; if it disagrees with the rules, skip the article.
- `AUTOPUBLISH=off` must always stop automatic acceptance, declining and publishing.
- Aggregator sources (GDELT) must drop articles from outlets read directly and count as one independence group.
- New sites go in `src/config/extra-sources.json` (validated at build). Do not add a source in code without an evidence label.

## Setup and takedown rules (added 14 November 2026)

- `/api/cron/setup` (CRON_SECRET bearer only) applies pending migrations and seeds the registry using `runSetup`; it must stay idempotent, never drop data, and never echo secret values (its configuration review lists names and statuses only). It relies on `outputFileTracingIncludes` in `next.config.ts` for the migration SQL and state boundaries.
- A 4xx robots.txt answer other than 429 means no rules; 429, 5xx and network errors stop the fetch (RFC 9309).
- `INGESTION_DISABLE` must always win over "all": a disabled source never runs, even when selected explicitly.
- GDELT queries must stay serialized (about 5.5 s apart) and at most two per scheduled run.

## Publisher text and product direction (added 17 November 2026)

- Publisher text must not appear on the site beyond `PUBLISHED_EXCERPT_CHARS` (default 0). Apply `displaySummary`/`publicationSummary` for anything derived from an article excerpt, on write and on read. Evidence rows publish outlet, headline and link only.
- The product goal is a Nigerian World Monitor (many layers, not only news). See `docs/NIGERIAN_WORLD_MONITOR_ROADMAP.md` before adding features, and do not add a single "instability" score.
- Aggregator country filters must check each article's own source country, not only the query.
